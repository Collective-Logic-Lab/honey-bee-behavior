# Honey Bee Behavior -- Contributing

Honey Bee Behavior is a scientific community repository including a number of explorations around the behavior of _Apis mellifera_ in eusocial situations. While the focus of the repository is serving our internal laboratory's investigation, we are open to collaboration with other scientific groups. In any case, the purpose of the repository should be considered as context for the following contribution guidelines.

## Using issues

Please use GitHub Issues liberally for suggesting improvements and fixes. We do not have a formal issues template, but it will be helpful in many cases particularly to identify the files and the environment (workstation OS, versions, etc.) you are working with when encountering a problem.

## Pull request workflow

The repository has work over a long period of time from an evolving roster of contributors, meaning that it is very easy for us to build up old code, branches, documents, and so on. For this reason, we request that contributors use a fork and pull-request workflow for submitting improvements:

1. Fork the repository to your own personal account, clone the fork to your workspace, and you are ready to explore.

2. **Please branch!** Create a branch in your fork, make your changes there, and open a pull request to this repository. Keep each PR focused on a coherent contribution, and briefly explain what you changed and why.

   > One great way to easily make a feature branch is using the newish `git switch -c <my-new-branch>` from the command line.

3. Make sure that when you are referencing data, you describe how to access/work with/integrate those data either in your code comments or updated documentation.

We’ll use the PR to discuss the contribution and any revisions. The repository admins will handle merges.

## Releases

We do not yet use releases in this repository, but this may change at some point soon.

## Coding Agents

If you use a coding agent, it is your responsibility to make sure that you (and your agents) follow the instructions in `AGENTS.md`. You are responsible for reviewing and understanding the work you submit and should be able to discuss its purpose, assumptions, checks, and uncertainties.
